The Resilience Budget

A resilient module boundary buys recompilation-free evolution at a runtime cost. This measures which kinds of change actually happen across 714 consecutive releases of 111 C and C++ libraries — and therefore which resilience mechanisms earn that cost, and which are budget spent on events that almost never occur.

The blind spot

The most frequent hazard is the one no tool measures

Inline, in-class and template bodies

abidiff compares DWARF types and ELF symbols. abi-compliance-checker compares declared interfaces. A change to the body of a header inline function, an in-class method, or a template produces no output and exit code 0 from either — even with --harmless. It is invisible by construction, not merely rare. Yet C++ copies exactly those bodies into every client that included the header.

At 5.0%, inline-body churn is 1× as frequent as struct-field additions (5.6%) and 7× as frequent as vtable changes (0.7%). Worst single releases: gmp@6.1.2+dfsg..6.2.0+dfsg changed 500 bodies; e2fsprogs@1.46.6..1.47.0 changed 93 bodies; gmp@6.2.1+dfsg1..6.3.0+dfsg changed 64 bodies. This is the strongest argument in the data for making cross-module inlining opt-in rather than automatic.

The SONAME is the only ABI-compatibility signal the C/C++ platform offers, and in this corpus it accompanies roughly one break in 34. That is the background condition a resilient boundary competes against — not a careful versioning discipline, but an unenforced convention.

Least stable in the corpus, by binary-breaking transitions: intel-gmmlib 8/9, sane-backends 8/9, hunspell 8/8, libwps 7/9, srt 7/8, snappy 7/8, libzstd 6/9, libde265 6/9.

The verdict

Would a resilient boundary have saved the release?

Three framings, because they answer different questions. The first asks what survives at the linker level; the second what survives without recompiling — which is what a resilient boundary is for; the third also counts a changed inline body as a hazard, since a client may still be running the old copy.

Why the two rows differ, and why it matters

Adding an enum case moves no byte, so abidiff — correctly, for its purpose — does not call it an ABI break; neither does a changed inline body. Score only binary breakage and the enum and inlining mechanisms are credited with zero by construction. Under the framings that match what resilience is for: 68 of 229 affected releases are fully rescued (29.7%); opaque layout is load-bearing for 46, non-frozen enums for 30, resilient dispatch for 1. Counting changed inline bodies as a hazard too, opt-in inlining becomes load-bearing for 25 of 84 rescues.

The ceiling is the real finding: even under the generous framing, 70.3% of affected releases contain a removed symbol or a changed signature. Resilience buys evolution headroom, not immunity — it converts a class of breaks that is common and mechanical into a non-event, while leaving untouched the class that arises from deliberate API redesign.

Method

How the measurement is made

Everything runs in one C++26 tool, abistudy, in five idempotent stages. libabigail is linked as a library and its diff tree is walked directly — no abidiff text is parsed — so every count traces to a specific IR node, and the per-object artefacts keep the event lists that justify each number. Header bodies are indexed with the libclang C API. A 30-case ground-truth suite (synthetic libraries with exactly one known change each, four of them negative controls) is compiled and pushed through the same code on every build; the calibration gate passes 30/30.

01

Default abidiff hides enum-case additions. They are filtered as harmless. The tool keeps the harmless categories, so they are counted.

02

--leaf-changes-only drops base-class insertions. The visitor reads the base-class maps of each class diff directly.

03

Types outside the public headers are attributed to the library. glibc's _IO_FILE or libstdc++'s std::vector change when the toolchain moves, and a library's private structs change freely. Each type event carries the DWARF declaring file, matched by basename against the -dev headers; 15,868 events on types not declared there were set aside.

04

Private ELF version nodes. Symbols whose version node says PRIVATE or INTERNAL are not API; 3,299 such events were set aside. --drop-private-types would not have caught them: it covers types, not functions.

05

abipkgdiff cannot compare across a SONAME rename. It pairs ELF files by filename and silently skips the mismatch. Shared objects are paired by SONAME stem instead.

06

Some libraries rename every symbol by policy. ICU suffixes each symbol with its version. Transitions whose churn is such a rename (1 here) are detected and excluded rather than left to dominate the totals.

Scope

What this does and does not establish

Selection is automatic, not curated. Libraries are the most-installed lib* packages by Debian popcon whose source ships both a -dbgsym and a -dev package, quota'd separately for C and C++.

"Consecutive releases" means consecutive upstream versions as packaged by Debian, deduplicated so Debian-revision-only rebuilds are not counted as library evolution. Debian may skip upstream releases, so a pair can span more than one.

Reachability is not usage. A layout-visible struct is one reachable from the public API; whether clients embed it rather than hold a pointer is not measured, so layout counts are an upper bound on real client breakage.

Header coverage is heuristic. Headers are parsed standalone with include paths guessed from the package layout; 0 transitions had poor coverage and their body counts are lower bounds.

Debug info was missing on one side for 15 transitions; those were compared on symbols alone and contribute no layout events.

Transitions are not independent samples: a library contributes up to nine. Per-library rates are in summary.json.
